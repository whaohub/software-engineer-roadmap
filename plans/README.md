# 每日计划目录

每个工作日一份 `YYYY-MM-DD.md`，文件入库，因此：

```bash
git log --oneline -- plans/          # 看每天的计划与提交历史
git show HEAD~2:plans/2026-11-05.md  # 回看某天的计划
make plan                            # 终端直接看最新一份（= 明天/今天的执行清单）
make plan-new                        # 生成下一天的空计划（模板）
```

## 规则

1. **一天一个文件**，命名 `YYYY-MM-DD.md`（不写"明天"这种相对词）
2. 每条任务必须写清 **入口 / 命令 / 验收 / 降级** 四项；验收只能是"某个测试名变绿"或"一张数字表"
3. 最多 **3 个执行块**（工作日 45-75 分钟，冲刺日 ≤90 分钟）；**同一个 block 只做一层**，不混算法 / 并发 / 文档
4. 收工时在底部 `## 复盘` 填 3 行，并把结论并入 `PROGRESS.md`；**旧日计划可删除**（历史用 `git log -- plans/` 查），避免目录膨胀
5. `NEXT.md` 只保留"当前一个单元"，历史细节留在 `plans/` 与 `PROGRESS.md`

## 与其它文件的关系

| 文件 | 时间粒度 | 作用 |
|---|---|---|
| `PLAN.md` | 半年 | 方向与阶段（基本不变） |
| `plans/YYYY-MM-DD.md` | 一天 | 今天的执行清单与复盘（每天新增） |
| `NEXT.md` | 一次会话 | 唯一"下一步"指针（每次收工更新） |
| `PROGRESS.md` | 里程碑 | 阶段状态 + 会话日志（每次收工追加） |
