# 准入自测与按需补给（决定"先补基础"还是"直接开工"）

> 本项目的立场：**不需要先学完 `cpp/01~09`**，只需要满足 3 个最小前提；
> 其余知识在撞到的时候现学（Just-in-Time），因为**没有落点的知识留不住**。

## 1. 三个最小前提（只有这三条是硬要求）

| # | 前提 | 为什么是硬要求 | 对应专题 |
|---|---|---|---|
| P1 | 能写 RAII 包装，并说清为什么资源类要禁拷贝或实现移动 | 句柄的生命周期全靠它 | `cpp/01` |
| P2 | 知道 `shared_ptr` 为什么是 16 字节、控制块里有什么 | 决定句柄能不能塞进 16 字节 | `cpp/04` |
| P3 | 能用 `std::atomic` 写引用计数，并说清 `--` 到 0 之后谁负责 `delete` | 引用计数是 M1 的并发核心 | `cpp/06` 的 10% |

其余（vtable 布局、内存序细节、allocator、ODR、协程）**都不作前置**，在 M2~M5 撞到再学。

## 2. 准入自测（5 题，每题 10 分钟，可开卷但禁止搜现成答案）

1. 写一个 `FileGuard`（RAII 包装 `FILE*`），说明为什么必须 `FileGuard(const FileGuard&) = delete`，
   并给出正确的移动构造实现。
2. `sizeof(std::shared_ptr<int>)` 是多少？控制块里至少有哪些字段？为什么 `shared_ptr` 要存两个指针？
3. 用 `std::atomic<int>` 写引用计数的 `retain()` / `release()`，其中 `release()` 减到 0 时要销毁对象 ——
   写出代码并说明为什么不能写成 `if (--cnt == 0)`。
4. 下面这段为什么可能永久阻塞？指出**丢失唤醒**发生的位置：
   ```cpp
   // 消费者
   while (q.empty()) cv.wait(lk);
   // 生产者
   q.push(x); { std::lock_guard<std::mutex> g(m); } cv.notify_one();
   ```
5. `std::move(x)` 之后 `x` 处于什么状态？举一个标准库类型，它的移动后状态**不等于空**（必须给出具体类型与原因）。

### 判定线

| 得分 | 结论 | 动作 |
|:--:|---|---|
| **4-5** | 直接开工 | 进入 M1 步骤 1（今天就能动手） |
| **3** | 缺 1 项 | 花 **2 小时**只补缺的那一项（见 §3），然后开工 |
| **0-2** | 缺地基 | 花 **5 小时**做 §3 的 P1+P2+P3 三个 20 行 demo，再开工 |

> 严格的意义在于：**这 5 题答不上来，M1 的 12 个用例你也看不懂为什么红**，
> 那时"项目驱动"就会退化成"抄实现"，比循序渐进更糟。

## 3. 最小补给包（只补缺的，不做全景复习）

| 缺口 | 补给内容（≤2 小时） | 产出（20 行 demo） |
|---|---|---|
| P1 | `cpp/01-object-lifetime/docs/Q001_RAII.md` 重读 + 手写 `FileGuard` | `cpp/01/.../src/file_guard.cpp` |
| P2 | `cpp/01/.../docs/Q002_对象生命周期.md` + 打印 `sizeof`/`use_count` | `cpp/04/.../src/handle_size.cpp`（顺便修好你 11-05 那个 demo：加 `sizeof` + 双 shared_ptr 泄漏对照） |
| P3 | `std::atomic` 的 `fetch_add/fetch_sub/memory_order` 文档一节 + 用 `-fsanitize=thread` 跑一遍 | `cpp/06/.../src/refcount_atomic.cpp` |

补给完成后**立刻回到 M1**，不要顺势把整个 `cpp/06` 学完 —— 那是 M2 的任务。

## 4. 什么时候必须停下来补前置（三条信号）

1. **同一个概念查了 3 次**（例：`memory_order` 反复查文档）→ 停下来补 1 小时，写一个 20 行验证程序
2. **60 分钟写不出一行能编译的代码，且不知道该查什么** → 说明缺的是整体图景，回去补对应 Q 文档
3. **测试是红的，但你无法解释为什么红** → 立刻停止改代码，先写清楚"我预期它做什么 / 它实际做了什么"

## 5. 反模式（出现即视为本次会话失败）

- ❌ 直接抄现成实现（iceoryx / folly / 别人的 blog 代码）→ 先写 `docs/ADR.md` 的取舍，再自己写
- ❌ 跳过 ADR 直接编码 → 三个决策决定了后面 200 行的形状
- ❌ 只让测试变绿、不记录工具输出 → `docs/M1-*.md` 必须贴 ASan/TSan 原始片段
- ❌ 连续 2 天 0 commit → 降级为"每天 20 分钟只做一个小步"
- ❌ 顺手开始学 `cpp/02` 的全部理论 → 只在 M1 需要的那一小块上深挖
