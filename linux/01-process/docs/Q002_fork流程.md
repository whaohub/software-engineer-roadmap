# Q002: fork 流程

## 1. fork 系统调用概述

**fork** 是 UNIX/Linux 中创建新进程的核心系统调用。调用一次，**返回两次**：在父进程中返回子进程的 PID，在子进程中返回 0。

```c
#include <unistd.h>

pid_t fork(void);
```

- fork 成功后，会创建一个与父进程几乎完全相同的子进程
- 子进程是父进程的**拷贝**：复制了父进程的代码段、数据段、堆、栈、打开的文件描述符表等
- fork 之后，两个进程**并发执行**，各自拥有独立的地址空间

```c
printf("before fork, pid=%d\n", getpid());
pid_t pid = fork();
if (pid == 0) {
    // 子进程代码
} else if (pid > 0) {
    // 父进程代码
}
```

> 一句话总结：**fork 让"一个进程"分裂成"两个进程"，代码从 fork 处兵分两路。**

---

## 2. fork 返回值详解

fork 的返回值是理解它的关键：

| 返回值 | 出现在哪个进程 | 含义 |
|:-----:|:--------------|:-----|
| **0** | 子进程 | 标识"我是子进程" |
| **> 0** | 父进程 | 返回子进程的 PID，标识"我是父进程" |
| **-1** | 父进程 | 创建失败，`errno` 说明原因 |

```c
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>

int main() {
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        exit(1);
    } else if (pid == 0) {
        printf("子进程: pid=%d, 我的父进程 ppid=%d\n", getpid(), getppid());
    } else {
        printf("父进程: pid=%d, 我创建的子进程 pid=%d\n", getpid(), pid);
    }
    return 0;
}
```

> 常见误区：**fork 不是"返回两次"，而是"调用一次，返回两次"**——父进程和子进程各自从 fork 返回一次，返回值不同。

## 3. 写时复制 COW（Copy-on-Write）

### 3.1 传统 fork 的问题

早期的 fork 会**立即复制**父进程的整个地址空间，成本高昂：

- 拷贝所有物理页 → 慢
- 内存占用翻倍 → 浪费

### 3.2 Linux 的 COW 机制

Linux 的 fork 采用**写时复制**优化：

| 阶段 | 行为 |
|------|------|
| **fork 时** | 父子进程**共享**同一份物理页，页表项标记为**只读** |
| **只读访问** | 双方正常读取，不复制，效率高 |
| **写入访问** | 触发**缺页异常（page fault）**，内核才复制该物理页，并分别映射为可写 |

```
        fork 之后（共享只读）
父进程 ──┐
         ├──> 物理页 P（标记只读）
子进程 ──┘

        父进程写入页 P 时
父进程 ──> 复制出 P'（父可写）
子进程 ──> 继续用 P（变为可写）
```

### 3.3 COW 的价值

1. **fork 变快**：只是复制页表 + 标记只读，不复制物理内存
2. **省内存**：不修改的部分永远共享
3. **配合 exec**：fork 后通常立即 exec（加载新程序），此时完全不需要复制，COW 让 `fork + exec` 模式几乎零拷贝

> 一句话总结：**COW 让 fork 变成"近乎 O(1) 的页表拷贝"，只有在真正写入时才付出复制代价。**

## 4. 父子进程执行顺序

**fork 之后，父进程和子进程谁先执行是不确定的**，由内核调度器决定：

- 不能假设"父进程先执行"
- 也不能假设"子进程先执行"
- 现代 Linux 通常让**子进程先运行**（减少 COW 复制概率），但这只是实现细节，不是保证

```c
#include <unistd.h>
#include <stdio.h>

int main() {
    pid_t pid = fork();
    if (pid == 0) {
        printf("子进程先运行了\n");
    } else {
        printf("父进程先运行了\n");
    }
    return 0;
}
```

多次运行上面的程序，输出顺序可能不同。如果需要保证顺序，必须显式同步：

| 同步手段 | 说明 |
|---------|------|
| `wait` / `waitpid` | 父进程阻塞等待子进程结束 |
| 信号 `SIGCHLD` | 子进程退出时通知父进程 |
| 管道 / 共享内存 + 锁 | 进程间显式协调 |

## 5. fork 失败的原因

fork 返回 -1 的常见原因：

| errno | 原因 | 说明 |
|:-----:|:-----|:-----|
| **EAGAIN** | 进程数达上限 | 超出系统允许的进程总数（`pid_max`）或当前用户的进程数上限（`ulimit -u`） |
| **ENOMEM** | 内存不足 | 内核无法分配足够的 `task_struct` 或页表 |

```bash
cat /proc/sys/kernel/pid_max   # 系统最大 PID / 进程数
ulimit -u                      # 当前用户可创建的进程数上限
```

> 无限 fork（如 `while (1) fork();`）会很快耗尽进程数或内存，导致系统卡死，务必在生产代码中控制 fork 次数。

## 6. 常见面试陷阱

### 6.1 fork 一次调用，n 次循环产生多少子进程？

```c
for (int i = 0; i < 3; i++) {
    fork();
}
```

每次 fork 后父子进程**都会继续循环**，因此子进程数量是 **2ⁿ − 1 = 7** 个。

### 6.2 全局变量是"副本"，修改互不影响

```c
int g = 10;
pid_t pid = fork();
if (pid == 0) {
    g = 100;             // 子进程修改自己的副本
}
// 父进程中的 g 仍然是 10
```

逻辑上父子进程各有一份数据副本；物理上因 COW 共享，直到写入才分离。

### 6.3 缓冲区内容被"重复打印"

```c
printf("hello ");        // 若 stdout 未刷新，数据还在用户态缓冲区
fork();                  // 缓冲区被复制给子进程
// 最终可能打印两遍 "hello "
```

- stdout 是终端时**行缓冲**（`\n` 会刷新）
- 重定向到文件时是**全缓冲**，fork 前未刷新的数据会被子进程复制一份
- 解决：fork 前 `fflush(stdout)` 或 `setvbuf` 关闭缓冲

### 6.4 fork 与 exec 通常成对出现

fork 复制出来的子进程还要继续运行父进程的代码，如果想运行别的程序，必须配合 `exec` 系列函数加载新映像，这就是 Q003 的内容。

---

## 7. 面试要点总结

1. **一次调用两次返回**：子进程返回 0，父进程返回子进程 PID，失败返回 -1
2. **COW**：fork 时共享只读物理页，写入才触发缺页复制 → 快、省内存
3. **执行顺序不确定**：由调度器决定，需要同步必须显式用 wait/信号/锁
4. **资源是副本**：数据段、堆、栈、文件描述符表都被复制（逻辑上），修改互不影响
5. **缓冲区陷阱**：fork 前务必 `fflush`，否则未刷新数据会被复制导致重复输出
