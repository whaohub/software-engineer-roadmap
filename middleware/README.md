## 作品 1：mini-ipc（阶段 C 的核心交付物）

| 验收项 | 目标 |
|---|---|
| 功能 | 跨进程 pub/sub、topic 动态注册、订阅者崩溃后不泄漏 |
| 机制 | 共享内存 + 无锁 SPSC 队列 + 定长内存池 + 跨进程引用计数 |
| 数据 | 1MB 消息 p50 < 10µs、p99 < 30µs；对比 UDP loopback 的延迟与抖动量级差 |
| 质量 | gtest 覆盖并发边界 + `-fsanitize=thread` 通过 + README 里给出失败模式分析 |
| 加分 | 加 trace 后开销 < 1%；支持零拷贝把 tensor 直接交给推理侧 |

## 与执行管理（EM）的衔接（可选延伸，不读 AUTOSAR 规范）

中间件决定「数据怎么走」，执行管理决定「**谁在什么时候、用多少资源去收发**」。
这三点在你日常工作中最容易出问题，直接写成案例文档即可（不需要啃规范）：

1. **启动时序**：EM 启动进程 → 中间件端口/共享内存就绪 → 才能对外提供服务
2. **资源预算**：每个进程的 CPU/内存预算里，必须包含中间件缓冲与序列化开销
3. **故障传播**：订阅者崩溃 → 共享内存回收 → EM 重启进程 → 健康状态上报
